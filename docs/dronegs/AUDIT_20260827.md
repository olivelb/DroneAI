## Delivered, ordered by expected benefit / risk

1. **A1 — conditional opacity-SH device storage.** The scalar-opacity path now
   allocates neither the 15-float gradient nor the 15-float2 Adam moments.
   Saving: exactly `capacity * 180` bytes in these device allocations, i.e.
   270,000,000 bytes / 257.49 MiB at 1,500,000 slots. This is an extrapolation
   from the allocation formula, not a measured whole-process VRAM delta at
   that population. Split resets, CPU compaction, snapshot and restore respect
   the optional storage. The 296-byte Gaussian AoS, PLY layout and V4/V5
   checkpoint layout remain unchanged; disabled checkpoint moments are zeroed
   on the host. Removing those remaining 60 AoS bytes is **not** included.
2. **D2 — bounded network recovery.** Each raw/compressed GET may retry twice
   after fetch/stream network failures or HTTP 408/429/500/502/503/504. Backoff
   is 150/300 ms plus 0–99 ms jitter. Valid `Retry-After` is honored up to 2 s;
   longer server delays fail without an early retry. The scheduler releases
   its concurrency slot while sleeping, requeues with the current priority,
   and honors cancellation. No retries for corrupt ranges/lengths or permanent
   HTTP failures. HTTP Zstd decoding TypeErrors retain immediate raw fallback;
   explicit Zstd decompression failures also retain fallback. The fallback
   has its own bounded attempts (at most six GETs across two representations).
   `rangeScheduler.networkRetries` reports scheduled retries. No background
   polling, signed-URL renewal or indefinite cut restart is added.
3. **Prefetch utility race.** Promotion used to increment useful bytes before
   completion. The adaptive controller explicitly rejects useful > completed,
   so a queued/in-flight promotion could invalidate a planning sample. Useful
   counters now advance with successful completion of a promoted request, or
   first critical memory-cache use of a completed prefetch. Failed transfers
   are not useful. Priority promotion remains immediate. Budget thresholds,
   final visible cut and rendering math are unchanged.
4. **Degenerate tiler partition I/O.** Coincident centers necessarily fail the
   midpoint split. The tiler now directly takes the existing stable count-split
   fallback, avoiding one full read and write of that work file. This halves
   partition passes **only for coincident-center nodes**, not general tiling
   time. Tests verify exact child bytes/order/count/bounds across odd/even
   populations and chunk boundaries. There is no new format, quantization,
   proxy strategy, source-id ordering or whole-file materialization.
5. **Strict transport bounds and documentation.** Reject unsafe range endpoints
   and Content-Range totals not beyond the endpoint. Correct Production V1
   scalar opacity, native checkpoint default 0 versus platform V1 7,500, and
   native version metadata. Clarify seeded scheduling versus cross-GPU bitwise
   identity. Do not silently change Production V1.

These changes do not claim a first-view/FPS speedup from unmeasured HTTP or
disk timing. Network recovery improves degraded-service behavior; the ordinary
successful path does not add a request or a delay.

## Remaining recommendations: not rejected as ineffective

The ordering below favors observability before a major algorithm/layout change.
There is no evidence yet to label the deferred architecture work ineffective.

| Audit item | Disposition and next acceptance gate |
|---|---|
| A3 refinement instrumentation | Delivered in dev.67: host-wall phase timings and logical transfer counters, optional frozen-checkpoint benchmark, CPU/CUDA/JSON contracts. No extra GPU fences; device submission is not kernel elapsed time. Exact synthetic parity passes; precise overhead and production-corpus/peak-process-VRAM measurements remain unqualified. See [evidence and limits](REFINEMENT_TELEMETRY.md). |
| A2 hot/cold or SoA | High-potential experiment after baseline capture. Keep PLY/checkpoint AoS at boundaries; measure projection/binning/Adam and conversion costs, not only field load efficiency. Require CPU/CUDA and resumed-run parity before promotion. |
| A4 GPU topology | Dev.68 moves Adam/refinement-state compaction to existing GPU scratch ([first qualification](GPU_COMPACTION_DEV68.md)); dev.69 adds Gaussian compaction ([second qualification](GPU_GAUSSIAN_COMPACTION_DEV69.md)). Dev.70 uses a compact pruning snapshot: 5M snapshot payload falls from 1.58 GB to 260 MB and fenced refinement from 1.243 to 0.461 s versus dev.69 ([qualification](PRUNING_SNAPSHOT_DEV70.md)). Dev.71 computes exact independent percentiles on at most four CPU threads: 5M fenced refinement falls from 0.468 to 0.318 s versus a fresh dev.70 reference, with byte-identical real/synthetic full checkpoints ([qualification and resource limits](PARALLEL_PERCENTILES_DEV71.md)). This is bounded CPU scheduling, not GPU percentile migration. Per-Gaussian CPU pruning and scoring/top-K remain. No full-training speedup claim. |
| C2 adversarial CUDA | Retain bounded oracle. Add seeded boundary families for depth, anisotropy, near-degenerate quaternions, alpha and covariance clamps; use one-sided expectations at non-differentiable boundaries, not invalid symmetric finite differences. Existing fixed CUDA fixtures are not this proposed broad property corpus. |
| D1 external Morton/Hilbert | Relevant to 100M+ populations, not delivered. Current proxy construction is already recursive bottom-up; replacing spatial partitioning is the missing architectural work. Compare total temporary bytes, peak disk/RSS, skewed inputs, deterministic leaf/proxy cuts and first-view latency. Balanced midpoint behavior is O(N log N); degenerate depth is bounded by configuration, not universally balanced. |
| D3 multi-scene camera paths | Required for product speed claims: freeze scene/bundle hashes, door→facade and long-travel paths, cold/warm HTTP/IndexedDB states, frame-time p50/p95/p99, load/commit time, bytes and VRAM. Previous Saint-Etienne approvals do not automatically cover this commit or other scenes. |
| A5 view support checks | Real worst-case O(views × initial Gaussians), but `any_of` normally stops early. Measure unsupported-crop setup first. Any spatial rejection must remain conservative relative to the exact projection. |
| B1 random/all | Already implemented as opt-in. Qualify black/active, black/all and random/all with identical datasets/seeds/budgets, held-out PSNR/SSIM/LPIPS plus foreground holes/alpha/silhouettes/ghosting. No default objective change here. |
| B2 opacity-SH on/off | Keep opt-in/custom. Multi-view geometry and opacity fidelity matter alongside image scores. Storage optimization is not evidence for or against the scientific feature. |
| B3 spatial-block/guard ring | Existing custom path. Freeze train/holdout/ignored sets and establish a separate Production V2 baseline; do not reuse V1 canary thresholds without qualification. |
| C1 architecture matrix | This lot runs on Ada only. Ampere, Turing and Blackwell plus long multi-seed production runs remain unqualified for this exact binary/source. Logical determinism is not a promise of cross-device PLY hashes. |
| D2 SHA/WASM remainder | `sha256()` already awaits asynchronous WebCrypto `subtle.digest`; Q96/stream preparation already use workers. Measure UI long tasks, buffer ownership/transfer copies and checksum elapsed time before adding a second hashing implementation. Asynchronous does not prove zero UI overhead, but the audit does not demonstrate a synchronous SHA hotspot. |
| Translation-unit refactor | Useful preparatory work, not a speed gain by itself. Extract one coherent subsystem with explicit ownership and unchanged license/provenance; do not combine a broad CUDA split with the SoA transition. |

Keep the bounded CPU/CUDA path as an oracle. FastGS's packed RGBA8 backward
checkpoints are a qualified approximation; do not relabel that path exact.
Packing remains opt-in: fewer objects did not improve the recorded cold
Saint-Etienne first LOD, so no default 2 MiB aggregation is promoted here.
